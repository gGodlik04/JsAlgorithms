1. Базовая идея React

React решает задачу: как обновить пользовательский интерфейс эффективно, когда состояние приложения меняется.

Основные принципы:

UI описывается как функция от состояния (UI = f(state)).

Вместо того чтобы руками работать с DOM (дорого, неудобно), React поддерживает свою абстракцию — Virtual DOM.

React сам решает, какие части реального DOM нужно обновить.

2. Virtual DOM

Virtual DOM (VDOM) — это обычные JS-объекты, описывающие структуру интерфейса (типы элементов, props, children).

Когда компонент возвращает JSX, он не создаёт реальный DOM — он создаёт виртуальное дерево.
Пример:

<div className="hello">Hi</div>

превратится в объект примерно такого вида:

{
type: "div",
props: { className: "hello", children: "Hi" }
}

3. Fiber architecture (сердце React c 16+)

До версии React 16 была рекурсивная модель reconciliation (дерево обходилось целиком). Но это блокировало основной поток.

Теперь React использует Fiber — это:

структура данных (каждый элемент дерева UI представлен Fiber node),

и алгоритм координации обновлений.

Каждый Fiber — это объект, который хранит:

тип узла (host component, functional/class component),

props,

ссылку на DOM-узел (если есть),

указатели на child, sibling, return (делают дерево двусвязным),

эффекты (что нужно сделать с DOM при коммите).

Fiber позволяет React:

разбивать работу на части (чтобы не блокировать UI),

прерывать/возобновлять рендер,

приоритизировать задачи (например, пользовательский ввод важнее, чем обновление невидимого списка).

4. Два этапа работы React
   (A) Render phase (reconciliation)

React сравнивает новый Virtual DOM (созданный после обновления состояния) со старым деревом Fiber.

Алгоритм diffing определяет, какие узлы изменились (сравнение по type и key).

Для каждого изменённого узла создаются effect tags: Placement (вставить), Update (обновить), Deletion (удалить).

Эта фаза может быть прервана (asynchronous, cooperative scheduling).

(B) Commit phase

Когда diff закончен, React атомарно применяет изменения к реальному DOM.

Этап commit синхронный и не может быть прерван (иначе мы получим «разорванный» UI).

Здесь вызываются lifecycle-хуки: componentDidMount, useEffect, componentDidUpdate.

5. React Reconciliation (diffing-алгоритм)

Чтобы быстро понять разницу между старым и новым деревом:

Если тип элемента (div, span, компонент) совпадает → React обновляет атрибуты.

Если тип разный → React удаляет старый узел и создаёт новый.

Для списков используется key — помогает сопоставлять элементы. Без key React будет удалять и пересоздавать узлы, даже если они похожи.

6. Scheduling и приоритеты

React работает в main thread (там же JS и layout/paint). Чтобы не блокировать интерфейс, React разбивает работу на части и использует:

Scheduler (пакет scheduler) — планирует, какие задачи с каким приоритетом выполнять,

приоритеты: Immediate, User-blocking, Normal, Low, Idle.

Например:

Нажатие клавиши → высокий приоритет (надо обновить быстро).

Обновление невидимой части списка → низкий приоритет.

7. Hooks и state

useState хранит состояние внутри Fiber-узла. Каждый вызов хука записывает значение в связанный список «хуков» внутри Fiber.

При обновлении setState React кладёт обновление в очередь (update queue).

Во время рендера React идёт по хукам в том же порядке и применяет обновления.

⚠️ Поэтому нельзя вызывать хуки условно — порядок вызовов должен оставаться стабильным, иначе React «собьётся» в своём списке.

8. Concurrent React

С приходом Concurrent Mode (React 18: automatic batching, concurrent features):

React может готовить новый UI в фоне, не блокируя интерфейс.

Если во время рендера приходит событие высокой важности (например, ввод текста), React может выбросить текущую работу и начать заново, чтобы не тормозить.

Suspense позволяет откладывать рендер до готовности данных (асинхронный UI).

9. ReactDOM и обновление настоящего DOM

React сам DOM не трогает напрямую в процессе diff.

Когда commit-фаза наступает, React вызывает host config (в случае ReactDOM — это DOM API: document.createElement, appendChild, setAttribute).

Для React Native — другая реализация host config (Bridge к нативным компонентам).
→ То есть React сам по себе не знает, как рендерить; рендерер (ReactDOM, React Native, React Three Fiber) отвечает за конкретную платформу.

10. Оптимизации

Batched updates: несколько setState внутри одного события объединяются.

Memoization: React.memo, useMemo, useCallback → предотвращают лишние пересчёты.

Key в списках → предотвращает лишние удаления/создания.

Lazy rendering / Suspense → откладывают ненужные части UI.

Offscreen rendering (новые фичи) — возможность готовить UI вне экрана.

11. Итоговый «жизненный цикл» обновления в React

Состояние меняется (setState / useState).

React помечает компонент «грязным» и ставит задачу в очередь Scheduler.

Во время render phase создаётся новый Virtual DOM и Fiber-дерево.

React сравнивает новое дерево с прошлым (diff).

Формируется список эффектов (что поменять в реальном DOM).

В commit phase изменения применяются к DOM.

Запускаются эффекты (useEffect, lifecycle).
